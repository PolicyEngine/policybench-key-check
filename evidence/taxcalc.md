## A. Running it

A1. Aging switch. `Data.__init__` sets aging off only when BOTH `gfactors is None and weights is None` (TC/data.py:87-88); one None and one not raises 'gfactors and weights are inconsistent' (data.py:91-92). With aging off, `increment_year` only adds one to the year (data.py:154-155) and `_extrapolate` is never called, so no input is grown; the weights file is never read and `s006` is not set from it (data.py:108-125).
A2. `start_year` must be a Python int (data.py:94-95). Records docstring gives the custom-data recipe: `Records(data=df, start_year=<year>, gfactors=None, weights=None)` (TC/records.py:35-37).
A3. Column handling on load (data.py:226-267): each DataFrame column whose name is a "read" variable in records_variables.json is kept; int-typed read variables are cast with `to_numpy(dtype=np.int32)` and float ones to float64 (data.py:229-240); every other column is silently dropped into `IGNORED_VARS` (data.py:241-242). Every read variable not supplied, and every calculated variable, is set to zeros (data.py:249-263). Missing a `required` read variable raises 'data missing one or more MUST_READ_VARS' (data.py:244-245).
A4. What Records rewrites or checks on load (TC/records.py:139-199): `exact` set to 1 for every row if `exact_calculations is True`, else 0 (records.py:142); `FLPDYR` overwritten with start_year (records.py:144); MARS must be in 1..5 (records.py:146-148); `num` set to 2 if MARS==2 else 1 (records.py:150); EIC must be in 0..3 (records.py:152-154); `e00200 == e00200p + e00200s`, `e00900 == e00900p + e00900s`, `e02100 == e02100p + e02100s` within 0.020001 or ValueError (records.py:156-166); `e00200s`, `e00900s`, `e02100s`, `k1bx14s` must be zero when MARS != 2 (records.py:168-178); `e00600 >= e00650` and `e01500 >= e01700` or ValueError (records.py:180-192); `PT_SSTB_income` must be 0 or 1 (records.py:194-196); `credit_claim_urn` is overwritten with `np.random.default_rng(seed=192837465).uniform(size=n)` for every row, so any supplied value is discarded and each row's draw depends on its position and the row count (records.py:198-199). No adjustment ratios when `adjust_ratios=None` (records.py:428-430).
A5. Calculator construction (TC/calculator.py:95-140): Policy and Records are deep-copied (99-106); if `policy.current_year < records.data_year` the policy is moved up to the data year (107-108); with `sync_years=True` (default) records are incremented until they reach the policy year (117-119). So `Records(start_year=2026, gfactors=None, weights=None)` plus a default `Policy()` gives a Calculator already at 2026 with no growth; `advance_to_year(y)` steps one year at a time and raises if y < current year (151-163). A 2025 run needs its own Records with start_year=2025 (a 2026 Records cannot go back).
A6. `calc_all()` (calculator.py:165-175) runs UBI, BenefitPrograms, `_calc_one_year`, LumpSumTax, ExpandIncome, AfterTaxIncome. `_calc_one_year` order (calculator.py:1423-1515): EI_PayrollTax, Adj, CapGainsLoss, AGIIncome, SSBenefits, AGI, MiscDed, ItemDed, AdditionalMedicareTax, StdDed, then TaxInc/SchXYZTax/GainsTax/NetInvIncTax/AMT three times, then F2441, EITC, PersonalTaxCredit, AmOppCreditParts, SchR, EducationTaxCredit, CharityCredit, ChildDepTaxCredit, NonrefundableCredits, AdditionalCTC, C1040, CTC_new, IITAX.
A7. Itemize-or-not is Tax-Calculator's own choice, not an input: it computes `c05800` (regular tax plus AMT, BEFORE any credit) once with the standard deduction and itemized parts zeroed, once with standard zeroed (calculator.py:1435-1466), and itemizes when `item_taxes < std_taxes`; when the two are within $0.01 and `std_taxes > 0` it itemizes iff itemized > standard (calculator.py:1484-1489). A unit owing $0 c05800 either way takes the standard deduction. No input forces itemizing (MIDR exists for MARS 3 only; see B). Inference: a unit whose credits, not c05800, change with the choice (e.g. via AGI-independent items) is not optimized on after-credit tax.

## C. Outputs (payroll and SE tax, from EI_PayrollTax, TC/calcfunctions.py:85-295)

C1. `ptax_was` holds BOTH shares, employee plus employer: ss_rate = FICA_ss_trt_employer + FICA_ss_trt_employee and mc_rate = FICA_mc_trt_employer + FICA_mc_trt_employee (calcfunctions.py:205-206); per spouse, OASDI = ss_rate * min(SS_Earnings_c, e00200x + pencon_x) and HI = mc_rate * (e00200x + pencon_x) (calcfunctions.py:215-227). So the FICA wage base is e00200p + pencon_p (gross wages), not e00200p. There is no employee-only output: the board's employee FICA equals FICA_ss_trt_employee * min(SS_Earnings_c, e00200p + pencon_p) + FICA_mc_trt_employee * (e00200p + pencon_p), plus the same for the spouse, which with equal rates is ptax_was - ptax_er_p - ptax_er_s or ptax_was / 2 (ptax_er_p/s = employer-rate part, calcfunctions.py:273-280). Additional Medicare Tax is NOT in ptax_was (see AdditionalMedicareTax). `payrolltax` = ptax_was + extra_payrolltax (reform-only OASDI above SS_Earnings_thd) (calcfunctions.py:257-262); setax is not in payrolltax at this point.
C2. `setax` holds BOTH halves of SE tax, per person: sey_p = e00900p + e02100p + k1bx14p (calcfunctions.py:209-211); seca_frac = 1 - 0.5*(ss_rate + mc_rate), i.e. 0.9235 at 2026 rates (231); net_sey_p = max(0, sey_p * seca_frac) and set to 0 when below SECA_Earnings_deminimus (233-241); OASDI part = ss_rate * min(net_sey_p, SS_Earnings_c - min(SS_Earnings_c, e00200p + pencon_p)) (243-247); HI part = mc_rate * net_sey_p (248-249); setax = sum over head and spouse (250-253). A loss for one spouse does not offset the other's SE earnings (each floored at 0 separately). Partnership SE earnings enter SE tax only through k1bx14p/k1bx14s. Wages reduce the OASDI room per spouse using gross wages including pencon.
C3. `c03260` = (1 - ALD_SelfEmploymentTax_hc) * 0.5 * setax, the deductible half (calcfunctions.py:288). `earned` = max(0, e00200p + e00200s + sey - c03260); `earned_p` = max(0, e00200p + sey_p - (1-hc)*0.5*setax_p) (calcfunctions.py:289-293). Earned income here uses e00200 (net of pencon), and sey includes farm and partnership SE amounts.

## C. Outputs (tax before refundable credits, refundable credits, iitax)

C4. `c09200` (C1040, TC/calcfunctions.py:4355-4530) = othertaxes + max(0, c05800 - c07100) (4517, 4529). `othertaxes` = e09700 + e09800 + e09900 + niit + setax + ptax_amc (4521-4526). So c09200 INCLUDES self-employment tax (both halves), Additional Medicare Tax, NIIT and the three input-only other taxes. `c05800` = regular tax plus AMT before credits (records_variables.json:664-667). `c07100` (4502-4514) = c07180 (CDCC nonref) + c07200 (Sch R) + c07600 + c07300 + c07400 + c07220 (CTC nonref) + c08000 + c07230 (education nonref) + c07240 + c07260 + odc + charity_credit + personal_nonrefundable_credit. Inference: a PE-comparable "income tax before refundable credits" built from Tax-Calculator is c09200 minus whichever of setax, ptax_amc, niit the PE variable leaves out; c09200 itself is never changed by soi_iitax (4764-4766).
C5. `refund` (IITAX, calcfunctions.py:4884-4892) = eitc (c59660) + c11070 (ACTC) + c10960 (refundable AOC) + recovery_rebate_credit + CDCC_refund + personal_refundable_credit + ctc_new + (c07220 if CTC_is_refundable) + (odc if ODC_is_refundable). Under 2026 current law the reform-only items should be zero (to confirm in the run).
C6. `iitax` depends on the policy switch `soi_iitax`, default FALSE from 2013 (TC/policy_current_law.json:320-333): with false, iitax = (c09200 - setax - e09800 - ptax_amc) - refund and payrolltax = ptax_was + extra_payrolltax + setax + e09800 + ptax_amc (calcfunctions.py:4905-4910); with true, iitax = c09200 - refund and payrolltax stays ptax_was. NIIT stays in iitax either way. So the default `payrolltax` output is employee+employer FICA plus SE tax plus Additional Medicare Tax, not the board's employee-side payroll tax.
